# WorkBuddy 桌面版 · 容器化部署说明

在 NAS（或任意 Linux 服务器）上用 Docker 跑**腾讯官方 WorkBuddy 桌面客户端**（Linux 版），通过浏览器使用：支持中文输入、画质自适应、收件箱传文件、24 小时常驻。

```
你的浏览器  ──HTTP:23880──▶  容器内 KasmVNC(Xvnc)  ──▶  fluxbox + fcitx5 + WorkBuddy(Electron)
你的浏览器  ──HTTP:23881──▶  容器内上传页  ──▶  /opt/wb/inbox（共享文件夹）
```

## 1. 能做什么 / 不能做什么

| 能 | 不能 |
|---|---|
| 跑**官方客户端本体**，登录你自己的账号，专家/资料库/定时任务都是真的 | 不是网页版重写，**后端始终在腾讯云**；断网、账号失效会直接影响使用 |
| 浏览器多端访问，同一会话保持（关掉浏览器不中断） | 碰不到 NAS 宿主文件，只能操作容器内挂载的目录 |
| 中文输入（fcitx5 拼音）、双向复制粘贴、文件上传 | 没有 GPU，软件渲染，**画面流畅度不如本地客户端** |
| 本地定时任务常驻（客户端在线才触发） | 云端定时任务本来就不依赖它在线 |

## 2. 前置条件

- x86_64 或 ARM64 的 NAS/服务器，Docker 20.10+ 与 Compose v2
- 能访问 **Docker Hub**（构建时拉 `debian:bookworm-slim`，约 30MB；国内慢就在 Docker 设置里配镜像加速）
- 能访问 `download.codebuddy.cn` 与官方更新接口（构建时自动取最新客户端并校验 sha256）
- 磁盘 ≥ 5GB（镜像约 2.5~3GB + 数据目录）

## 3. 部署（5 步）

### 3.1 解压到项目目录

```bash
mkdir -p /你的/路径/workbuddy && cd /你的/路径/workbuddy
unzip workbuddy-client-deploy.zip --strip-components=1    # 或 tar -xzf ... --strip-components=1
```

解压后应有：

```
Dockerfile            # 构建用
docker-compose.yml    # 唯一一份，创建项目时构建
bootstrap/            # entrypoint / kasmvnc 配置 / xstartup / 上传页 / 输入法配置
install.sh            # 可选：生成密码、建 inbox
DEPLOY.md             # 本文档
```

### 3.2 设置访问密码（可选但强烈建议）

```bash
bash install.sh --password '你的密码'     # 会写进 compose 与 vnc-password.txt
```

不用终端也行：直接改 `docker-compose.yml` 里的 `VNC_PASSWORD`。

### 3.3 新建 Compose 项目

极空间：「Docker → Compose → 新建项目」

1. 项目名称：`workbuddy`
2. **项目存储位置 = 刚才解压的目录**
3. 把 `docker-compose.yml` 全文粘进编辑框
4. **确认构建上下文为当前目录 `.`**
5. 创建

> 构建上下文选错会报 `COPY bootstrap/... not found`。

### 3.4 等待构建（10~15 分钟）

```
拉 debian:bookworm-slim（约 30MB）
→ apt 装 X11 / KasmVNC / Chromium / 输入法 / nodejs（约 600MB）
→ 查官方更新接口，取最新客户端版本与 sha256
→ 下载客户端（x64 约 430MB / 410MiB；arm64 约 400MB）并强制校验
→ 生成镜像 workbuddy-client:1.0.0 → 容器自动启动
```

构建成功后**再重建项目是秒级**（镜像已在本机）。

### 3.5 登录

浏览器打开 `http://<NAS-IP>:23880/` → 用户名 = `VNC_USER`（默认 `root`）、密码 = `VNC_PASSWORD` → 桌面里点 **Sign In** → 容器内 Chromium 打开官方登录页 → 微信扫码 → 自动回到客户端。

## 4. 日常使用

| 需求 | 做法 |
|---|---|
| 传文件 | 桌面右下角「📎 传文件」→ 拖文件 → 客户端里「+ → 添加文件 → 本地文件 → 收件箱」 |
| 或者走共享文件夹 | 把文件放进项目目录的 `inbox/`（可在 NAS 上设 SMB 共享） |
| 中文输入 | `Ctrl+Space` 切换，默认拼音 |
| 复制粘贴 | 双向可用（浏览器 ↔ 容器内） |
| 画面大小 | 默认跟随浏览器窗口（1:1，最清晰）；也可固定分辨率 |

## 5. 配置项

全部在 `docker-compose.yml` 的 `environment` 里：

| 变量 | 默认 | 说明 |
|---|---|---|
| `VNC_USER` | `root` | 登录用户名，可改成任意名字；**改后旧用户名立即失效** |
| `VNC_PASSWORD` | `iloveppcat` | 登录密码，**正式用请改** |
| `RESOLUTION` | `1440x900` | 自适应模式的初始尺寸 |
| `FIXED_RESOLUTION` | 空 | 填 `1280x800` 之类则固定、不跟随窗口 |
| `PERF_PROFILE` | `balanced` | 性能档位，见第 6 节 |
| `DEB_PLATFORM` | `auto` | `auto`/`x64`/`arm64` |
| `DEB_URL` + `DEB_SHA256` | 空 | 留空=自动取最新版；填了=钉死版本（**必须成对**，缺一个会报错退出） |
| `DESKTOP_PUBLIC_PORT` | `23880` | 浏览器访问的桌面端口，与 `ports` 左边一致 |
| `UPLOAD_PUBLIC_PORT` | `23881` | 上传页端口；设成 `none` 则不发布、桌面不显示按钮 |
| `KASM_PORT` / `UPLOAD_PORT` | `8444` / `6082` | **容器内**端口，一般不要动 |

## 6. 怎么改（常见修改一览）

改配置只有两种结果：**改了 `environment` 或 `ports` → 重新部署**（秒级，不重建镜像）；**改了 `Dockerfile` 或 `bootstrap/` 里的脚本 → 重新构建**（10~15 分钟）。

| 想改 | 改哪里 | 改完做什么 | 怎么验证 |
|---|---|---|---|
| 访问密码 | compose → `VNC_PASSWORD` | 重新部署 | 用新密码登录；旧密码应 401 |
| 登录用户名 | compose → `VNC_USER` | 重新部署 | 用新用户名登录；旧用户名应 401 |
| 桌面端口 | compose → `ports` 的 `23880` + `DESKTOP_PUBLIC_PORT` | 重新部署 | `sudo ss -lptn \| grep 新端口` 有监听 |
| 上传页端口 | compose → `ports` 的 `23881` + `UPLOAD_PUBLIC_PORT` | 重新部署 | 桌面右下角按钮指向新端口 |
| 不想要上传页 | 删掉 `ports` 里的 `23881` 行，`UPLOAD_PUBLIC_PORT: "none"` | 重新部署 | 桌面不再有「传文件」按钮 |
| 更流畅 / 更清晰 | compose → `PERF_PROFILE: lite` 或 `quality` | 重新构建* | 日志出现「性能档位：lite（画质 2~6，帧率 18fps）」 |
| 固定分辨率 | compose → `FIXED_RESOLUTION: "1280x800"` | 重新部署 | `xdpyinfo` 尺寸固定、不随窗口变 |
| 初始分辨率 | compose → `RESOLUTION` | 重新部署 | 首次连接时的桌面尺寸 |
| 钉死客户端版本 | compose → 同时填 `DEB_URL` 与 `DEB_SHA256` | 重新构建 | 日志出现「官方版本：<你填的版本>」或「自定义」 |
| 换 ARM 包 | compose → `DEB_PLATFORM: "arm64"` | 重新构建 | 日志出现「平台 arm64」 |
| 客户端防自动更新 | compose → `APP_READONLY: "on"` | 重新部署 | 日志出现「客户端目录已设为只读」 |
| 内存上限 | compose → `deploy.resources.limits.memory`（3g→6g） | 重新部署 | `docker inspect` 的 `oom=false` |
| 排障看日志不被刷 | compose → `restart: "no"` | 重新部署 | 容器停住，日志停在失败点 |
| 加自动重启 | 叠加 `docker-compose.autoheal.yml` 启动 | 重新部署 | `docker ps` 看到 autoheal 容器 |

\* `PERF_PROFILE` 是 entrypoint 读的变量，逻辑在 `bootstrap/entrypoint.sh` 里，所以改它需要**重新构建**；如果你只想立刻见效，先在浏览器 KasmVNC 设置里把 Quality 拉到 5~6。

修改时注意：

- **端口必须成对改**：`ports` 左边 + 对应 `*_PUBLIC_PORT`，漏一个会出现“能打开但按钮 404”。
- **`DEB_URL` / `DEB_SHA256` 必须成对**，只填一个 entrypoint 会直接退出并提示。
- 改完在极空间里点「重新部署 / 启动」即可；改了 `Dockerfile` 或 `bootstrap/` 才点「重新构建」。
- 登录态在 `home/` 卷里，任何修改都不会让它失效（除非你删掉这个目录）。

## 7. 性能调优

NAS 没有 GPU，画面靠 CPU 编码，所以要在“清晰”和“流畅”之间选：

| 档位 | 画质 | 帧率 | 说明 |
|---|---|---|---|
| `lite` | 2~6 | 18fps | 最流畅，小字略软；建议配 `FIXED_RESOLUTION: "1280x800"` |
| `balanced` | 4~8 | 24fps | 默认，日常够用 |
| `quality` | 6~9 | 30fps | 最清晰，明显更吃 CPU |

客户端侧还能再省（**不用重建，立刻生效**）：KasmVNC 设置里 Quality 调到 5~6、勾上 Dynamic quality、Scaling 选 None。

预期：纯软件渲染下能到“可用、打字滚动略有延迟”，达不到本地客户端的顺滑度。

## 8. 24 小时常驻

已内置：`restart: unless-stopped`（开机自启/崩溃拉起）、`init: true`（回收僵尸进程）、日志轮转 10MB×3、healthcheck、内存上限 3GB、可选 autoheal。

建议再加两件：

```bash
# 1) 每天 04:00 重启一次（放进 NAS 计划任务），清掉长跑积累的内存
bash scripts/restart-daily.sh

# 2) 让 unhealthy 容器自动重启（需要能拉 Docker Hub）
docker compose -f docker-compose.yml -f docker-compose.autoheal.yml up -d
```

注意：**关掉浏览器不影响它**。实测断开 40 秒后客户端进程继续运行、重连回到同一会话。

## 9. 升级与备份

| 操作 | 做法 |
|---|---|
| 升级客户端 | 保持 `DEB_URL` 为空 → 点「重新构建」（会重新取最新版）；或用 `DEB_URL`+`DEB_SHA256` 钉死某个版本 |
| 升级服务端配置 | 替换项目目录里的 `bootstrap/` 与 `Dockerfile`，重新构建 |
| 备份 | 备份 `home/`（登录态）、`state/`（密码与 VNC 配置）、`inbox/`（文件） |
| 恢复 | 目录放回原处，重新部署即可，**不用重新扫码** |

## 10. 排障

| 现象 | 原因与处理 |
|---|---|
| 一直「重启中」 | 先看 `sudo docker inspect workbuddy-client --format 'exit={{.State.ExitCode}} oom={{.State.OOMKilled}} err={{.State.Error}}'`：`err` 里写端口冲突 → 换端口；`oom=true` → 提高内存上限；`exit=1` 且无 `err` → 看日志里的 `错误：` |
| `bind: address already in use` | 宿主端口被占。只报第二个端口说明只有上传口冲突；改 `ports` 左边 + 对应 `*_PUBLIC_PORT`，**不用重新构建** |
| 日志反复 `KasmVNC 启动失败` | 容器崩溃后 `/tmp` 残留 X 锁；新版 entrypoint 启动前会自动清理，仍失败看 `logs/kasmvnc-start.log` |
| 8090/23880 打不开 | 构建还没完成，或容器未启动；等日志出现 `桌面已就绪` |
| 提示没有 node / 上传页 404 | 旧镜像；重新构建（新版 Dockerfile 已装 `nodejs`） |
| 反复弹密码框 | 改了 `VNC_PASSWORD` 没重建：删项目重建 |
| 打不出中文 | 输入法依赖 DBus 会话，镜像已处理；按 `Ctrl+Space` 切换 |
| 登录后没回到桌面 | `docker exec workbuddy-client xdg-mime query default x-scheme-handler/workbuddy` 应为 `workbuddy.desktop` |
| 画面卡顿 | 见第 6 节，切 `lite` 或客户端侧降画质 |

排障通用命令：

```bash
sudo docker logs --tail 50 workbuddy-client
sudo docker ps -a --format '{{.Names}}\t{{.Status}}\t{{.Ports}}' | grep workbuddy
sudo ss -lptnp | grep -E ':2388[01]'
```

## 11. 技术事实（已核对）

| 项 | 值 |
|---|---|
| 客户端来源 | 官方更新接口 `https://copilot.tencent.com/v2/update?platform=workbuddy-linux-{x64,arm64}-deb`（`www.workbuddy.cn` 同路径可兜底），返回 `version`/`url`/`sha256hash` |
| 当前版本 | `5.6.2.40046327` |
| 包大小 | x64 429,829,872 字节（430MB / 410MiB）；arm64 400,068,468 字节 |
| 校验 | 下载后 `sha256sum -c`，与接口给出的值逐位比对，不匹配即中止 |
| 桌面 | KasmVNC 1.5.2（HTTP + Basic 认证，无自签证书） |
| 输入法 | fcitx5 + 拼音，需独立 DBus 会话 |
| 浏览器 | 容器内 Chromium，用于完成登录回调（`x-scheme-handler/workbuddy`） |

官方提供 Linux 版（deb/rpm，x64 与 arm64），但走应用商店分发：下载页只写「请到系统应用商店下载」，不给直链，也没有公开 Docker 镜像。更新接口可用——所以构建时自动取包，不硬编码版本号。

## 12. 局限

- 非官方支持形态：官方支持 Windows/macOS 桌面端与手机端，Linux 包走应用商店分发。
- 软件渲染：视频、三维类页面会掉帧。
- 登录态过期需重新扫码（多端登录会互踢）。
- 客户端自动更新不要去点，容器里升级请走「重新构建」。
- 不要把 23880 直接暴露到公网；如需外网访问，前面加 HTTPS 反代并换强密码。

## 附：docker-compose.yml（完整带注释）

> 与部署包内的 `docker-compose.yml` 逐字节一致，可直接整段粘贴。注释不会被极空间破坏；即使被吃掉也不影响运行。

```yaml
# ============================================================
# WorkBuddy 官方 Linux 客户端 · 容器化
# 适用于：极空间 / 群晖 / 任意支持 docker compose 的 Linux
# ------------------------------------------------------------
# 唯一部署方式：**创建项目时构建**
#   1. 部署包解压到项目目录（目录里必须有 Dockerfile 与 bootstrap/）
#   2. 「Docker → Compose → 新建项目」，项目位置 = 该目录
#   3. 粘贴本文件内容，确认构建上下文为当前目录 “.”，创建
#
# 构建过程（约 10~15 分钟，只需一次）：
#   拉 debian:bookworm-slim → 装 X11/KasmVNC/Chromium/输入法/nodejs
#   → 查官方更新接口取最新客户端 → 下载并校验 sha256 → 生成镜像
# 构建完成后容器自动启动；以后重建项目是秒级（镜像已在本地）
# ------------------------------------------------------------
# 整理：泡泡猫 · 公众号 paopaocat888
# ============================================================

services:
  workbuddy-client:

    # ---- 镜像来源：从项目目录里的 Dockerfile 构建 ----
    build:
      context: .                  # 构建上下文 = 项目目录（极空间会提示确认，选错会报 COPY not found）
      dockerfile: Dockerfile      # 包内根目录的 Dockerfile（已按 bootstrap/ 布局写好）
    image: workbuddy-client:1.0.0 # 构建产物打这个 tag，重建/复用都认它
    container_name: workbuddy-client   # 固定容器名：日志、健康检查、脚本命令都按它写

    # ---- 运行策略 ----
    restart: unless-stopped       # NAS 开机自启、崩溃自动拉起；手动 stop 后不再自启
    # ↑ 排障期可临时改成 "no"：容器退出后不再重试，日志能稳定停在失败点
    init: true                    # 用 tini 当 1 号进程，回收僵尸进程（反复重启不会堆积）

    # ---- 端口映射：左边是浏览器访问的宿主端口，右边是容器内端口（不要改右边）----
    ports:
      - "23880:8444"              # 远程桌面（KasmVNC，HTTP + Basic 认证）
      - "23881:6082"              # 收件箱上传页（VNC 没有文件通道，用它代替拖拽）
      # 端口被占用时只改左边，并把下面对应的 *_PUBLIC_PORT 一起改

    # ---- 运行参数 ----
    environment:
      TZ: Asia/Shanghai

      # 桌面分辨率：allow_resize 打开时这只是初始值，连上后会跟随浏览器窗口（1:1 最清晰）
      RESOLUTION: "1440x900"
      # 想固定不跟随就填，例如 "1280x800"（改完 entrypoint 会自动关掉 allow_resize）
      FIXED_RESOLUTION: ""

      # 性能档位（NAS 无 GPU，靠 CPU 编码，清晰度与流畅度只能二选一）：
      #   lite     画质 2~6 / 18fps，最流畅，小字略软（建议配 FIXED_RESOLUTION: "1280x800"）
      #   balanced 画质 4~8 / 24fps，默认，日常够用
      #   quality  画质 6~9 / 30fps，最清晰，明显更吃 CPU
      PERF_PROFILE: "balanced"

      # 容器内端口，一般不要动（改了要同步上面的 ports 右边）
      KASM_PORT: "8444"
      UPLOAD_PORT: "6082"

      # 浏览器实际访问的端口：必须与 ports 左边一致
      DESKTOP_PUBLIC_PORT: "23880"   # 只用于打印访问地址
      UPLOAD_PUBLIC_PORT: "23881"    # 桌面右下角「传文件」按钮指向它
      # 上传页不想暴露端口时设成 "none"：不注入按钮，文件改走 SMB 收件箱

      # 客户端版本与平台
      DEB_PLATFORM: "auto"        # auto 按系统架构选；也可强制 x64 / arm64
      DEB_URL: ""                 # 留空=查官方更新接口取最新版；填了就用这个地址
      DEB_SHA256: ""              # 与 DEB_URL 配对使用（强制校验）；只填一个会报错退出

      VNC_USER: "root"            # 登录用户名，可改成任意名字（改后旧用户名立即失效）
      VNC_PASSWORD: "iloveppcat"  # 登录密码，正式使用请改掉

    # ---- 持久化目录：app 与 bootstrap 在镜像里，这里只挂需要保留的数据（相对路径，按项目目录解析）----
    volumes:
      - ./home:/opt/wb/home       # 登录态，删了要重新扫码登录（最重要，务必备份）
      - ./logs:/opt/wb/logs       # 运行日志（含 kasmvnc-start.log）
      - ./state:/opt/wb/state     # vnc-password.txt、KasmVNC 配置
      - ./inbox:/opt/wb/inbox     # 收件箱，可在 NAS 上设为 SMB 共享

    # ---- 资源共享 ----
    shm_size: "1gb"               # Chromium 需要足够共享内存，太小会崩标签页

    # ---- 健康检查：每分钟用 Basic 认证敲一下桌面，5 分钟后才开始判定（躲开首次构建后的启动慢）----
    healthcheck:
      test: ["CMD-SHELL", "curl -fsS -u \"$${VNC_USER:-root}:$$(cat /opt/wb/state/vnc-password.txt 2>/dev/null || echo x)\" http://127.0.0.1:8444/ >/dev/null || exit 1"]
      interval: 60s
      timeout: 10s
      retries: 3
      start_period: 300s

    # ---- 失控保护：超过 3g 被 OOM 杀掉并由 restart 拉起（比拖垮 NAS 好）----
    # 如果日志出现 oom=true 的反复重启，把这里调大到 4g~6g
    deploy:
      resources:
        limits:
          memory: 3g

    # ---- 给 autoheal 用的标记（配合 docker-compose.autoheal.yml 才会生效）----
    labels:
      autoheal: "true"

    # ---- 日志轮转：不限制的话 json-file 会一直涨，把磁盘吃满 ----
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "3"
```
