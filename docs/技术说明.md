# WorkBuddy 官方客户端 · 容器化

跑的是**腾讯官方 WorkBuddy 桌面端本体**（官方 Linux `.deb`），不是复刻、不是第三方实现。登录你自己的 WorkBuddy 账号后，专家·技能·连接器、资料库、定时任务、项目空间——都是官方真实能力，数据仍在腾讯云。

容器只承担三件事：**虚拟屏幕 + 客户端 + 网页远程操作**。

## 已实测（2026-11-16，Debian 12 / 无 GPU / 无 KVM）

## 远程桌面：KasmVNC

| 项 | 默认值 | 说明 |
|---|---|---|
| 端口 | 容器内 `8444` | compose 里映射 `23880:8444`，浏览器直接开 `http://<极空间IP>:23880/` |
| 认证 | HTTP + Basic | 用户名 = `VNC_USER`（默认 `root`，可改），密码 = `VNC_PASSWORD`（compose 预置 `iloveppcat`；真留空才随机生成并写进 `state/vnc-password.txt`） |
| 画质 | jpeg/webp **恒定 9**，lossless 阈值 9 | 配置在 `docker/kasmvnc.yaml`；不再用 8~9 动态区间，避免文字偶尔被压糊 |
| 缩放 | `bilinear` | 缩小窗口时不出现台阶锯齿 |
| 剪贴板 | 双向 | 宿主机复制的文字可以直接粘进 WorkBuddy，反之亦然 |
| 分辨率 | **自适应** | `allow_resize: true` + `desktop.resolution` 作初始值：连上来后桌面会按浏览器画布改尺寸（实测 1280×800 → 1680×1000 跟随），1:1 无缩放，文字最锐 |
| 桌面按钮 | 「📎 传文件」 | 启动时给 KasmVNC 入口页注入一段脚本，点击新开上传页；端口由 `UPLOAD_PUBLIC_PORT` 决定 |

> KasmVNC 在**构建阶段**安装（从 GitHub 拉约 2.5MB）。构建时拉不动可加 `--build-arg KASM_URL=镜像地址`。

### 分辨率怎么调（三种）

| 想要的效果 | 做法 |
|---|---|
| **自适应**（默认） | 什么都不用做：桌面跟着浏览器窗口变，1:1 不缩放；改窗口大小后客户端会自动请求远端改尺寸 |
| 手动对齐某一次 | KasmVNC 面板 **Displays → Native Resolution**，按当前窗口定一次 |
| 固定不跟随 | compose 里设 `FIXED_RESOLUTION: "2560x1440"`（会自动关掉 `allow_resize` 并写进配置）；留空即自适应 |

> 换分辨率时 fluxbox 会重设壁纸，容器里缺 `feh` 会弹报错窗——镜像已装 `feh`，实测 0 弹窗。

## 画质与中文输入（两个必须配的坑）

**画质发虚的两个来源**：① 远程桌面默认走有损 JPEG 编码（文字边缘出振铃）；② 虚拟屏幕与浏览器窗口尺寸不一致时被缩放。
解法已固化：分辨率 1920×1080，`kasmvnc.yaml` 里把 jpeg/webp 质量拉到 9、lossless 阈值 9、缩放算法设 `bilinear`；面板里点 `Native Resolution` 可让远端跟随浏览器尺寸。下面是旧参数（上）与新参数（下）同一区域的放大对比：

![画质对比：上=默认，下=无损](docs/05-quality-compare.png)

**中文输入法必须三件套齐全**，缺一个都只表现为"打不出中文"：

| 要素 | 不配的后果 | 脚本里的处理 |
|---|---|---|
| `fcitx5` + `fcitx5-chinese-addons` | 完全没有输入法 | apt 安装，profile 预置 pinyin 为默认 |
| **独立 DBus 会话**（`dbus-launch`） | 进程能起，但候选框永远不出（最容易踩） | 启动时 `eval $(dbus-launch --sh-syntax)` 并导出 |
| `GTK_IM_MODULE=fcitx` 等环境变量 | GTK/Electron 不把按键交给输入法 | 给客户端和 Chromium 一并导出 |

切换：`Ctrl+Space` 中英切换，候选用数字键或空格选字。要注意环境变量必须在**客户端启动前**就绪，事后改无效——改完要重启客户端进程。

## 传文件：为什么"拖进窗口"不行，以及三种可行办法

**先把事实说清楚**：远程桌面这条协议（RFB）**没有文件通道**。

- `x11vnc`：不支持文件传输（老牌 VNC server，只有画面与键鼠）
- `noVNC`（早期方案，现已弃用）：网页客户端，同样没有上传能力
- `KasmVNC` 单机版（本方案的默认桌面）：我为这件事专门装了一版实测，侧栏只有 `Keys / Clipboard / Fullscreen / Displays / Settings`，**没有 File transfer** —— 那是 Kasm Workspaces 商业版才有的能力

所以宿主机文件"拖进 WorkBuddy 窗口"在任何 VNC 方案里都不可能。要原生拖拽，只能上企业级网关（如 Apache Guacamole 的 RDP 驱动器重定向、或云桌面的文件重定向）。

本方案给的是**收件箱**，实测可用：

| 方式 | 怎么用 | 适合 |
|---|---|---|
| ① 收件箱上传页（内置） | **桌面右下角「📎 传文件」按钮**点一下就能打开（`http://<主机IP>:23881/`），文件拖进网页 → 落进容器 `/opt/wb/inbox` → 客户端里「**+ → 添加文件 → 本地文件 → 收件箱**」 | 随手传几个文件 |
| ② NAS 共享目录 | 把宿主机的 `…/workbuddy/inbox` 加成 SMB 共享，在电脑/手机资源管理器里直接拖进去；容器与宿主机是同一个目录 | 批量、大文件 |
| ③ 容器内下载 | 在容器里的 Chromium 打开网盘/网页直接下载，文件天然在容器内 | 从网盘取文件 |

![桌面右下角的「传文件」按钮](docs/08-upload-button.png)

![收件箱上传页](docs/06-inbox-upload.png)

上传页是零依赖 Node 小服务（`docker/upload-server.mjs`），单文件上限默认 512MB，落地文件名会自动去重。

### 把收件箱做成 SMB 共享（一次配好，长期用）

1. 在极空间「文件」里建一个**共享文件夹**下的目录，例如 `/vol1/1000/共享/workbuddy-inbox`
   （放在共享文件夹下，SMB 才共享得到；不要放在 docker 私有目录里）
2. 极空间「设置 → 共享服务 / SMB」里确认该共享文件夹已启用（默认多数是开的）
3. compose 里把这一行指向它：

   ```yaml
   volumes:
     - /vol1/1000/共享/workbuddy-inbox:/opt/wb/inbox
   ```

4. 之后在 Windows 资源管理器输入 `\\<极空间IP>\共享\workbuddy-inbox`，macOS 用 `smb://<极空间IP>/共享/workbuddy-inbox`，
   把文件拖进去——它同时在容器里的 `/opt/wb/inbox`，客户端「+ → 添加文件 → 本地文件 → 收件箱」即可选中。

> 注意：SMB 写入的文件属主是你的登录用户、权限多为 644，容器里以 root 读取没有障碍；如果你在极空间把这个共享设为只读，容器就只能读不能收，上传页会报错。

## 24 小时在线

**关掉浏览器不等于停掉它**：KasmVNC 服务端（Xvnc）与客户端都在容器里，浏览器只是看画面的终端。实测断开 40 秒后，客户端进程 uptime 继续增长、Xvnc 仍在，重连回到同一个会话。KasmVNC 的 `auto_shutdown`（无用户会话超时）我们没开，所以断连不会回收会话。

已内置的常驻加固：

| 项 | 作用 |
|---|---|
| `restart: unless-stopped` | NAS 开机自启、崩溃自动拉起 |
| `init: true` | tini 回收僵尸进程（反复重启不会堆积） |
| 日志轮转 `10m × 3` | 防止 json-file 无限增长 |
| `healthcheck` | 每分钟探测桌面是否可访问（Basic 认证 + 密码文件） |
| `deploy.resources.limits.memory: 3g` | 失控时被 OOM 重启，而不是拖垮 NAS |
| `labels: autoheal: "true"` | 配合可选 override 实现 unhealthy 自动重启 |

需要你在 NAS 上补两件（脚本已给）：

```bash
# 1) 每天 04:00 重启一次（放极空间「计划任务」）
bash scripts/restart-daily.sh

# 2) 想要 unhealthy 自动重启（需能拉 Docker Hub）
docker compose -f docker-compose.yml -f docker-compose.autoheal.yml up -d
```

还要知道的两点：① 登录态过期需要重新扫码（多端登录会互踢）；② 云端定时任务不依赖它在线，**本地定时任务必须它在线**。

## 能力边界（先看这个，避免预期错位）

- **后端永远在腾讯云**。容器是客户端外壳：断网、账号失效、腾讯改协议，都会直接影响可用性。
- **碰不到 NAS 宿主文件**。桌面端的"本地文件"任务只能操作容器内路径（`/opt/wb/home`、`/opt/wb/data` 等挂载卷）；云端定时任务、资料库不受影响。
- **没有 GPU**，软件渲染，视频/三维类页面吃 CPU、会掉帧。
- **x86_64 与 ARM64 都支持**：官方更新接口同时提供 `linux-x64-deb` 与 `linux-arm64-deb`（构建时按 `TARGETARCH` 自动选）。
- **非官方支持形态**。官方支持 Windows/macOS 桌面端与手机端；Linux 包存在但走应用商店分发。出问题时可退回"在你 Windows 电脑上装官方版"。

## 版本来源（不写死）

官方下载页只写“请到系统应用商店下载”，没有公开直链；但更新接口会给出真实地址与校验值：

```bash
curl -s 'https://copilot.tencent.com/v2/update?platform=workbuddy-linux-x64-deb'
# {"version":"5.6.2.40046327","url":"https://download.codebuddy.cn/.../WorkBuddy-linux-x64-deb-...deb","sha256hash":"12149ad8…"}
```

所以 Dockerfile 与 entrypoint 都**不硬编码版本号**：构建/启动时先查接口（`copilot.tencent.com`，失败回退 `www.workbuddy.cn`），拿到 `url` 与 `sha256hash` 后下载并强制校验；也可用 `DEB_URL`/`DEB_SHA256` 显式指定版本。平台按 `x86_64→x64`、`aarch64/arm64→arm64` 自动选择。

### 客户端版本与平台（三个环境变量）

| 变量 | 默认 | 说明 |
|---|---|---|
| `DEB_PLATFORM` | `auto` | `auto` 按 `uname -m` 判断；也可显式 `x64` / `arm64`（非法值会警告并回落 auto） |
| `DEB_URL` | 空 | 空 = 查官方更新接口取最新版；填了就用这个地址 |
| `DEB_SHA256` | 空 | 与 `DEB_URL` 配对使用；**只给其中一个会直接报错**，避免“以为钉死版本其实走了自动解析” |

构建模式另有 `--build-arg DEB_PLATFORM=x64|arm64`、`--build-arg DEB_URL=… --build-arg DEB_SHA256=…`。

完整部署手册见 [`deploy/部署说明.md`](deploy/部署说明.md)（含配置项、性能调优、24h 常驻、排障）。

## 部署方式：创建项目时构建（唯一方式）

依赖、KasmVNC、官方客户端都在**构建阶段**装好，构建完直接可用。之后重建项目是秒级。

| 阶段 | 做什么 | 耗时 |
|---|---|---|
| 拉基础镜像 | `debian:bookworm-slim` | 30MB，看网速 |
| 装依赖 | X11 / KasmVNC / Chromium / 输入法 | ~600MB |
| 取客户端 | 查官方更新接口拿最新版与 sha256，下载并**强制校验** | 400~430MB |
| 出镜像 | `workbuddy-client:1.0.0`，容器自动启动 | 秒级 |

前提：**极空间能访问 Docker Hub**（拉基础镜像）。拉不动就在 Docker 设置里配镜像加速。

## 部署（一条命令，或 6 步手动）

有终端的话最快：

```bash
cd /你想要的目录
bash install.sh                 # 自动解包、建收件箱、生成密码、填进 compose
# 或：bash install.sh /vol1/1000/docker/workbuddy
```

它**不猜平台路径**——只认参数里的目标目录或当前目录；compose 用的是相对路径（`./home`、`./inbox` 等），因此换人换机器都不用改文件。

下面是手动路线（等价）：

## 部署（极空间，6 步）

1. 在极空间建一个目录（**随便叫什么、放哪个卷都行**，下文称 `<项目目录>`），把部署包解进去：

   ```bash
   cd <项目目录>
   tar -xzf workbuddy-client-deploy.tar.gz --strip-components=1
   ```

   解压后 `bootstrap/` 里是启动脚本，`inbox/` 是收件箱（不存在就 `mkdir inbox`）。

2. 要换密码就改一处（默认预置 `iloveppcat`）：

   ```yaml
   VNC_PASSWORD: "iloveppcat"
   ```

   **不用改路径**：compose 用的是相对路径 `./home`、`./logs`、`./state`、`./inbox`，按「项目目录」解析；
   客户端的 `app/` 与 `bootstrap/` 在镜像里，不占宿主目录。

3. 极空间「Docker → Compose → 新建项目」，**项目位置选上面的 `<项目目录>`**，粘贴 `docker-compose.yml`，确认构建上下文为 `.`，创建（创建即构建）。
   （相对路径的基准就是这个项目目录，选错了容器起不来。）

4. **首次构建 10~15 分钟**：拉基础镜像 → apt 装 X11/VNC/Chromium（约 600MB）→ 查接口取最新客户端 → 下载（约 400~430MB，sha256 校验）→ 生成 `workbuddy-client:1.0.0` → 容器自动启动。之后再重建是秒级。

5. 浏览器打开（KasmVNC）：

   ```
   http://<极空间IP>:23880/        # 用户 root，密码 = VNC_PASSWORD
   ```

   传文件见「传文件」一节：SMB 共享收件箱，或另开 `http://<极空间IP>:23881/` 拖上去

6. 看到官方登录页 → 点 **Sign In** → 容器内的 Chromium 会打开登录页 → 扫码或用手机号登录 → 浏览器跳 `workbuddy://` 自动交回客户端 → 进入工作台。

## 登录机制（最容易踩的三个点）

1. **必须有浏览器且是默认浏览器**。客户端走 `shell.openExternal`，容器里没浏览器就只会显示 "Browser didn't open automatically?"。
   → entrypoint 装了 Debian `chromium`，并包了一层 `--no-sandbox --no-first-run`（root 运行必须）。
2. **必须注册 `workbuddy://` 协议**，否则登录完回不到客户端。
   → entrypoint 写 `/usr/share/applications/workbuddy.desktop` 并 `xdg-mime default` 注册。
3. **登录态在卷里**：`/opt/wb/home`。想退出登录/换账号，停容器后删这个目录即可。

## 排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动即失败：`bind: address already in use` | 宿主 23880/23881 被别的服务占用 | 换成 23880/23881（三处一起改：桌面、收件箱、`UPLOAD_PUBLIC_PORT`） |
| 23880 打不开 | 容器还在首次安装 | 看 `docker logs workbuddy-client`，等 `桌面已就绪` |
| 浏览器反复弹密码框 / 密码错 | `VNC_PASSWORD` 改了但没重建容器 | `docker compose up -d --force-recreate`；忘了密码看 `/opt/wb/state/vnc-password.txt` |
| 页面卡在 "Browser didn't open automatically?" | 浏览器没起或默认浏览器没设 | 点 Retry Sign In；或 `docker exec -it workbuddy-client bash` 里 `BROWSER=/usr/local/bin/wb-chromium xdg-open <登录链接>` |
| 登录完成但客户端没反应 | 协议回调没注册 | `docker exec` 里执行 `xdg-mime query default x-scheme-handler/workbuddy` 应返回 `workbuddy.desktop` |
| 中文显示成方块 | 缺中文字体 | entrypoint 已装 `fonts-wqy-zenhei fonts-noto-cjk`；自定义镜像别漏 |
| 客户端闪退 | 缺库或 Chromium 沙箱 | 看 `/opt/wb/logs/workbuddy.log`；确认启动参数带 `--no-sandbox` |
| 首次下载 deb 失败 | 网络到 `download.codebuddy.cn` 不通 | 手动下载同名 deb 放进 `/opt/wb/state/`，或改 `DEB_URL` 为内网镜像 |

## 安全

- KasmVNC 默认跑**纯 HTTP + Basic 认证**（为了少一层自签名证书的麻烦）：只在内网用，或前面加一层 HTTPS 反代（极空间域名、Nginx Proxy Manager 都行）；要自带 HTTPS 就把 `kasmvnc.yaml` 里 `ssl.require_ssl` 改回 `true`。
- **务必设 `VNC_PASSWORD`**，不设等于把整个桌面（含你的登录态）交给任何能访问 23880 的人。
- 不要把 23880 直接映射到公网。
- 客户端会把登录凭据存在 `/opt/wb/home`，备份这个目录等于备份账号，注意存放位置。
